# 题材分析引擎设计稿 v0

> 文档定位：HerPulse「海外女性向互动内容热点追踪」的核心引擎设计——如何从海量多语言内容中抽取**多维题材设定点**、计算热度趋势、并给出可信的「为什么火」解释。
> 版本：v0.6（M5 数据接入采集器已就绪）　日期：2026-09-14　状态：全链路端到端就绪——语料→真实抽取→去量纲热度→看板；采集器 fetchers.py 就绪（Reddit/AO3），真实抓取待海外网络环境；真实 baseline 宏平均 F1 0.943

---

## 0. 背景与目标

题材是 HerPulse 的**核心壁垒**。前两轮原型已验证：只给「分类 + 数字」没有「释义 + 来源 + 案例」，可用性接近于零；而把题材当「一维关系标签」更是外行做法。

本引擎的目标是回答三个问题：

1. **观众为什么被这个作品/角色吸引？** —— 把一段内容拆成多维设定点的叠加，而不是一个模糊标签。
2. **什么在涨、为什么涨？** —— 区分「单个设定点升温」「新组合配方升温」「新词涌现」三种信号。
3. **这个结论可不可信？** —— 每个抽取结果带原文证据、可复现、有金标集背书，杜绝「数字垃圾」。

## 1. 维度模型 v3（含 6 项已拍板决策 + P0 修订）

### 1.1 最终维度结构

基于两轮多 Agent 评审 + 6 项拍板决策 + P0 修订（MECE 修复 / 情绪基调独立 / 颗粒度统一），最终模型如下：

```
题材分析引擎
├── 核心题材维度（7 个）            → 进入「题材热度」主榜
│   ├── 1 关系动态
│   ├── 2 人物性格                  ← 病娇迁入（MECE 单归属）
│   ├── 3 情绪基调·体验              ← P0 新增：治愈/沙雕/爽文打脸/意难平/大女主等
│   ├── 4 职业·年龄
│   ├── 5 外观设定点                 ← 决策①：单列「素材热点」看板，不进题材主榜
│   ├── 6 世界观·场景
│   └── 7 交互·玩法
├── 信号层：社区·二创向度            → 决策④：计入题材热度权重（ship/OTP/同人产量）
└── 梗/meme 追踪层（独立）           ← 决策②：单独追踪，独立生命周期
```

**关键结构变化（相对 v2）：**
- 核心维度从 6 增至 **7**：新增「情绪基调·体验」维度，把治愈/沙雕/爽文打脸/意难平/甜宠/虐恋从关系动态拆出（它们描述整作体验风格，不是关系结构）。
- **MECE 修复**：病娇从「关系动态·禁忌越界」迁入「人物性格」（与傲娇/腹黑同族）；跨维度词（霸总↔总裁、年下↔奶狗、悬疑推理↔推理解谜、恶魔系↔恶魔地狱↔恶魔角 等）通过 `cross_refs` 记录次引用**不计数**，主维度决定单归属。
- **颗粒度统一**：叶子设定点必须同时满足「用户会主动检索 + 能凭一句话证据直接判定 + 跨作品可复现」，不满足者降入新词提案池或梗/meme 层。
- `外观设定点` 仍被抽取，但**路由到独立的「素材热点」看板**（它信号弱但买量素材价值高，混进题材主榜会污染立项判断）。
- `社区·二创向度` 从「纯信号层」升级为**参与热度计算的加权因子**（决策④）。
- 新增 **梗/meme 独立追踪层**，与「可持续追踪的设定点」彻底分离，避免长尾噪声污染词表。

### 1.2 三个热度信号（产品要分别接住）

| 信号 | 定义 | 给谁用 | 数据来源 |
|---|---|---|---|
| **单点升温** | 某设定点声量突增（如「兽耳」欧美 3 天 +90%） | 买量（找素材热点） | 设定点热度时序 |
| **组合配方升温** | 某几个设定点的**组合**是新且涨的（如「星际×年下×兽耳×养成」） | 策划（立项金矿） | 同内容多维度共现聚合 |
| **新词涌现** | 词表里没有的设定点冒出（新审美词/职业梗） | 运营（抢跑新风口） | LLM `new:true` 提案 |

### 1.3 颗粒度：三层受控词表

```
维度（Dimension） → 中类（Category） → 设定点（Setting Point，叶子受控词表）
```

- **叶子是受控词表**：只有「转正」的设定点才进叶子，杜绝 LLM 自由发挥导致的不归一。
- **每个设定点带 4 个字段**：`定义` + `多语言别名(en/ja/ko)` + `是否高频且影响选材` + `版本号`。

## 2. 设定点「转正」门槛与生命周期判定（决策⑥：AI 自动设定）

> 拍板：设定点最低热度阈值 + 生命周期判定标准，**由 AI 依据历史分布自动设定**，而非拍脑袋固定值。

### 2.1 热度阈值（AI 自适应）

**不用固定绝对值的理由**：不同市场（欧美/日韩）、不同平台（X/TikTok/AO3）的声量量级差 2-3 个数量级，一个绝对阈值必然失真。

**AI 自适应机制**：
- 对每个「维度 × 市场」单独建立过去 90 天的声量分布。
- **进入观察池阈值 = median + 1.5 × 1.4826 × MAD**；**进入热点阈值 = median + 3.0 × 1.4826 × MAD**（且环比 ≥ +50%）。
- MAD（中位数绝对偏差）抗噪、对长尾/离群稳健，优于 P75/P90 分位（分位需人工定档且对离群敏感）；每周滚动重算，阈值随大盘自动漂移，不依赖人工调参。

### 2.2 生命周期判定（AI 时序分析）

每个设定点用时间序列判定所处阶段：

| 阶段 | 判定规则（AI 拟合） | 动作 |
|---|---|---|
| 萌芽期 emerging | 声量 < 观察阈值 且斜率转正 | 进观察池，不推送 |
| 成长期 growing | 声量在观察阈值–热点阈值，7 天斜率 > 0 | 推送买量/运营 |
| 成熟期 mature | 声量 ≥ 热点阈值，斜率趋平 | 策划评估立项 |
| 衰退期 declining | 半衰期拟合：声量从峰值回落 > 50% | 标记，准备归档 |

**转正三条件（三者同时满足才进受控词表，否则留在「新词提案池」观察）：**
1. **跨作品可复现**：出现在 ≥ N 部作品（N 初始 5，AI 可调）。
2. **用户主动检索/筛选**：搜索量或平台 tag 使用量达到阈值。
3. **热度有持续期**：非月抛梗（生命周期 > 30 天，而非 1-2 周的 meme）。

> 「月抛梗」自动分流到**梗/meme 追踪层**，不进题材词表。

## 3. 多语言归一（决策⑤：AI 维护）

拍板：英/日/韩标签映射与本地化由 **AI 维护**，人只做抽检。

**AI 维护的四个环节：**

1. **别名自动生成**：给定一个设定点种子（如「年下」），AI 生成它在英/日/韩的候选别名（`younger ML` / `年下（toshishita）` / `연하`），人工抽检后入库。
2. **跨语言聚类**：对抽取出的 raw tag 做跨语言 embedding 聚类，把「耳钉男 / ピアス男子 / 피어싱남」归到同一设定点 ID。
3. **语义漂移告警**：对已音译但语义漂移的词（`yandere` 在欧美更偏「占有欲」、`tsundere` 更偏「傲娇」）持续监控，漂移超阈值时提示人工复核。
4. **无对等词处理**：`年下 / 师尊 / 无限流 / 快穿` 这类英文圈无对等词的，保留原词 + 英文解释性别名（如 `无限流 → "unlimited flow (infinite-dimension survival)"`），不强行翻译。

**已知硬骨头（需持续投入）：**
- 欧美偏「关系型」标签（enemies-to-lovers / fake-dating / slow-burn），日韩偏「性格/身份型」标签（ヤンデレ / 年下 / 帝王），两套语料天然错位。
- 归一化的目标不是「翻译」，而是「映射到同一个设定点 ID」。

## 4. 抽取 Prompt 全文（生产级 v0）

> 这是引擎的质量核心。设计原则：**受控词表约束 + 强制证据引用 + 严格 JSON + 新词提案 + 宁缺毋滥**。

### 4.1 系统提示词

```text
你是 HerPulse 的题材设定点抽取器。你的任务是从给定的「海外女性向互动内容」文本中，
抽取出多维度的题材设定点（setting points），输出严格 JSON。

【输入】一段原始内容（可能是作品简介、角色介绍、社媒帖子、评论、PV 文案，语言为中文/英文/日文/韩文之一）。

【受控词表】你只能从下面的词表中选 tag。每个维度列出的设定点已经过人工确认，含定义。
—— 词表注入（按维度 RAG，只注入相关片段，见 4.2）——

【输出 JSON Schema】（严格遵守，不要输出任何 JSON 以外的文字）
{
  "dimensions": {
    "relationship":   [{"tag": "关系动态设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}],
    "personality":    [{"tag": "人物性格设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}],
    "mood":           [{"tag": "情绪基调体验设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}],
    "occupation_age": [{"tag": "职业年龄设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}],
    "appearance":     [{"tag": "外观设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}],
    "world":          [{"tag": "世界观场景设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}],
    "gameplay":       [{"tag": "交互玩法设定点名", "confidence": 0.0-1.0, "evidence": "原文引用"}]
  },
  "signal_layer": {"ship_otp": [...], "fanworks": [...], "controversy": [...]},
  "new_words": [{"dimension": "维度名", "candidate": "候选新词", "evidence": "原文引用", "reason": "为什么认为它是新设定点"}],
  "language": "zh|en|ja|ko"
}

【铁律】
1. evidence 必须逐字引用原文，禁止改写、禁止编造。无法引用原文的抽取一律舍弃。
2. 宁缺毋滥：不命中任何受控词表就输出空数组 []，禁止硬塞近义词。
3. 词表里没有的候选词，放进 new_words（new:true 语义），绝不允许塞进现有维度数组。
4. 每个 tag 必须与受控词表的规范名完全一致，禁止自己造同义词。
5. confidence 是你对该 tag 与原文匹配的确信度：0.9+ 显式原文；0.7-0.9 需推断；<0.7 不确定，可放 new_words 或舍弃。
6. 多语言输入：识别原文语言填入 language，tag 一律映射回受控词表的中文规范名（或受控词表内约定的英文规范名）。
```

### 4.2 词表注入策略（避免塞满上下文）

- 受控词表按维度存储（见 `seed_vocabulary.json`）。
- 抽取时**按维度做 RAG**：先对原文做一次粗粒度分类，只把相关维度的设定点定义注入 prompt，而非全量词表。
- 全量词表过大时（> 200 设定点），只注入「高频且影响选材」标记为 true 的子集 + 该维度中类名，控制 token。

## 5. 热度计算公式（P1 重做：去量纲 + Shapley 校准 + MAD 阈值）

### 5.1 信号预处理（去量纲）

评审指出的量纲错误：四信号量级差 2-3 个数量级（社媒声量几十万条 vs 二创几千篇 vs 搜索 0-100 指数 vs 榜单 1-100 名次），直接加权会让大数量级信号主导、其余权重失效；且榜单名次越小越好（需反向）。

修复：每个信号先 `log1p` 压缩 → 按「市场×平台」z-score 标准化；榜单名次反向。

```
z_s    = (log1p(x_s) − μ_s) / σ_s              # social / fanwork / search
z_rank = (log1p(1/rank) − μ_rank) / σ_rank     # 名次反向后标准化
```

### 5.2 单设定点热度指数

```
H(tag, m, t) = Σ w_s · z_s × decay(t)
```

- `m` = 市场（欧美/日韩），`t` = 时间窗口（日/周）。
- 权重 `w_s` 在标准化后按「目标占比」真正生效（不再被量级淹没）。
- **权重校准（替代人工定值）**：用下载/收入做回归，Shapley 归因（标准化线性回归系数）反推各信号权重，已落地 `src/heat_engine.py::shapley_weights()`。初始值 `social 0.40 / fanwork 0.30 / search 0.20 / rank 0.10` 仅作冷启动，正式值由 Shapley 校准替代（决策④：二创反映 fandom 忠诚度与长尾热度）。
- **时间衰减** `decay(t) = e^(-Δt / half_life)`，`half_life` 由 AI 按各维度拟合（梗类短、世界观类长）。

### 5.3 阈值（滚动中位数 + MAD 抗噪）

```
观察阈值 = median + 1.5 × 1.4826 × MAD
热点阈值 = median + 3.0 × 1.4826 × MAD
```
（已落地 `src/heat_engine.py::threshold_mad()`，替代 P75/P90 分位。）

### 5.4 组合配方热度

```
配方热度 = min(成员设定点热度) × 共现提升系数(co-occurrence lift)
```
- 用**共现提升系数**而非简单求和，避免「人人都有的基础设定点」虚高。
- 只有「共现显著高于独立出现概率」的组合才被判定为「配方」（如 lift > 1.5）。

### 5.5 与商业价值交叉校验

> 声量 ≠ 收入。看板必须把「热度曲线」与「下载/收入曲线」并排，供策划判断「吵得凶但能不能赚钱」。

## 6. 黄金评测集构造方法与评测脚本

### 6.1 构造方法（分层抽样）

1. **样本来源**：作品简介 / 角色介绍 / 社媒热帖 / 评论 / PV 文案，按「维度 × 语言(zh/en/ja/ko) × 热度档」分层抽样，目标 **≥ 200 条**。
2. **标注**：每维度设定点由领域专家标注「正/负」，**双人独立标注 + 仲裁**（kappa 系数衡量一致性）。
3. **评测集冻结**：评测集与训练/few-shot 完全隔离，prompt 每改一行都要重跑。

### 6.2 指标

- **Precision / Recall / F1**（按维度微平均 + 宏平均）：唯一可信质量尺。
- **一致性**：同一文本抽取 N 次，结果集合应稳定（Jaccard ≥ 0.9）。
- **覆盖率**：`unknown` / 漏标比例，暴露词表缺口。

### 6.3 评测脚本

见 `src/eval_harness.py`（可直接运行，输入金标集 + 预测 JSON，输出 P/R/F1/一致性/覆盖率报告）。

M2 已落地为可运行抽取链（`src/extract.py` + `src/llm_backends.py`），配套：
- 抽取器 `src/extract.py`：词表 RAG 注入 + few-shot + 可插拔后端（mock / OpenAI 兼容），输出 `predictions.json`（喂评测）+ `extractions_detail.json`（带 evidence 审计）。
- 种子金标集 `data/gold_set_seed.json`：32 条真实素材（中/英/日/韩），7 维度手工标注。**注意：这是开发侧自标种子版，仅用于链路冒烟与回归，不作为真实抽取质量背书（自证风险，见 P1 事项 rRslmm）。**
- few-shot 数据化 `data/fewshot_examples.json`（与金标集隔离）。
- 冒烟结果：mock 后端覆盖率 86.7%、微平均 F1 0.34（高召回低精确，规则后端典型病），证明链路已通、且**真实 F1 必须接真 LLM 才能得出**。

**M2 真实 baseline（DeepSeek V4 Pro，thinking=disabled，temperature=0）已跑通，详见 `baseline评测报告_deepseek-v4-pro.md`：**
- 宏平均 F1 **0.927**，7 维度全部达标：relationship 0.955 / personality 0.864 / mood 0.905 / occupation_age 0.895 / appearance 1.0 / world 0.962 / gameplay 0.909。
- 一致性 0.972（≥0.9 ✅），覆盖率 0.951（136/143，≥0.85 ✅）。
